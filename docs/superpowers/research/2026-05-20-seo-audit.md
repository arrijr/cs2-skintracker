# SEO Baseline Audit — CS2 Skin Tracker (2026-05-20)

Source: searchfit-seo:seo-auditor agent run during Sprint 2 planning.

**Overall score: 22 / 100.** Site technically up but the SEO-critical surface (15k skin pages) is invisible to Google.

## Top 5 Findings

### 1. `/skins/[skinId]/page.tsx:4` starts with `"use client"`
Entire skin detail page (title, h1, price, image) renders client-side after `useEffect` fetch. Initial HTML payload is the loading skeleton. **15,071 potential landing pages = 15,071 empty shells to Googlebot.** Single biggest blocker.

### 2. `/skins/[skinId]` has no `generateMetadata`
Impossible while client-rendered. Every skin page inherits the static `"CS2 Skin Price Tracker"` title from `frontend/src/app/layout.tsx:42`. Textbook duplicate-content / cannibalisation on 15k URLs.

### 3. `frontend/src/app/sitemap.ts:20-66` lists only 7 static routes + blog posts
Zero skin URLs, zero item URLs, zero case URLs. Even if SSR ships tomorrow, Google has no discovery path for the programmatic pages. Also uses `dynamic = 'force-dynamic'` (line 5) — self-DDoS risk once skins are added.

### 4. No JSON-LD `Product` schema anywhere
Blog has `BlogPostSchema.tsx` (Article) — pattern proven. Skin and item detail pages have nothing. Forfeits Google merchant rich-results (price, availability) on every commerce query. Reference: `frontend/src/app/blog/[slug]/page.tsx:20-71`.

### 5. Integer URL slugs + variant duplication
URLs are `/skins/4711` (zero topical signal). Schema's `variantOf` field (`backend/prisma/schema.prisma:62`) means up to 20 near-identical rows per base skin (wear × StatTrak × Souvenir). No canonical strategy = mass intra-site duplication once indexed.

## Top 3 Fixes for Sprint 2

### 1. Convert `/skins/[skinId]/page.tsx` to Server Component
Move client body to `_components/SkinDetailClient.tsx`. Add `generateMetadata` + ISR (`next: { revalidate: 3600 }`). Reference: `frontend/src/app/items/[id]/page.tsx` already does this correctly. **Effort: M.** Without this, fixes 2-14 deliver <20% of their value.

### 2. Paginated sitemap + JSON-LD `Product` schema in same PR
Use Next 15's `generateSitemaps()` to chunk 15k skins into pages of 5000. Add new `frontend/src/components/skins/SkinProductSchema.tsx` mirroring `BlogPostSchema.tsx`. **Effort: S+S.** Ship together so Google discovers + parses pages in one pass.

### 3. Switch URLs to `/skins/[slug]` with 301 from `/skins/[id]` BEFORE submitting to GSC
Use `slugify(marketHashName)`. Adding slugs after indexing triggers re-crawl penalty. Also pick canonical strategy for variants (recommend: variant pages with `rel=canonical` to base skin). **Effort: M.**

## Blockers for Programmatic SEO of 15k Pages

- **SSR conversion (fix #1) is non-negotiable.** Everything else is downstream.
- **`NEXT_PUBLIC_SITE_URL` must be set in Vercel** for both `production` and `preview` envs before sitemap submission. Robots fallback in `frontend/src/app/robots.ts:5` points at `https://cs2-skintracker.com` which may not resolve. **Add to CEO checklist §3.**
- **Price-data backfill** (Sprint 2's actual scope) must reach top 5k skins before GSC submission, or rich-result eligibility fails on majority of pages. Suggest `noindex` wrapper in `generateMetadata` while `priceLatest === null`.

## What's Working

- `frontend/src/app/robots.ts` correct (Next 15 convention, env-driven baseUrl).
- `frontend/middleware.ts:14` leaves `/skins(.*)` public — no Clerk gate blocking Googlebot.
- `next.config.ts:27-37` pre-whitelists all Steam CDN hostnames for `next/image` — swap from raw `<img>` is plug-and-play.
- `next/font` with `display: "swap"` on all 3 fonts in `frontend/src/app/layout.tsx:6-23` — zero CLS.
- Blog stack (`frontend/src/app/blog/[slug]/page.tsx`) is the reference impl: SSR + `generateMetadata` + OG + Twitter + JSON-LD + canonical. Port that pattern to skins.
